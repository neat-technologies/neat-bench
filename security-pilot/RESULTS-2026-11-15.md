# Security bench: k=3 results, 2026-11-15

Three runs on one box on 2026-11-15, 54 agent trials, $390.45 of API spend. Every number below is
rebuilt from the artifacts under `runs/` by `node scripts/summarize-runs.mjs` (the full output is at
the end of this file). How to re-run any of it: [REPRODUCE.md](REPRODUCE.md).

**Status: not a citable benchmark result.** One of the four apps is contaminated for the arms
without NEAT, the design cannot yet separate NEAT's effect from the model's, and two apps cannot
run their own test suites on the box. Read "What these runs do not show" before using any number.

  redeployed app for "actually works". A criterion that cannot be evaluated is `unverified`, and a
  trial with an unverified criterion is not a pass.

What the results support, and no more:

- **uptime-kuma.** Every arm produced a verified fix in every trial. Bare Sonnet was the cheapest
  arm. NEAT plus Sonnet cost 2.6 to 3.3 times what bare Sonnet did, for the same outcome.
- **paperless-ngx.** Bare Sonnet removed the vulnerability in all three trials for less than either
  NEAT arm. No arm can be verified here, because the app's test suite does not run on the box.
- **nodegoat.** Both bare models left advisories in place in every trial (bare Opus left swig and
  underscore, bare Sonnet left swig). Both NEAT arms cleared all six in every trial. This is the one
  app where NEAT changed the outcome. It rests on the corpus's definition of "reachable" (any
  first-party import), and the app's test suite does not run on the box.
- **gitea.** Not usable for the bare arms. See the next section.

## What these runs do not show

1. **gitea is contaminated for the arms without NEAT.** The harness cloned the full repository
   before checking out the vulnerable commit, so upstream's later history, including the commit that
   fixes the target, was in the checkout. All three bare-opus trials and two of three bare-sonnet
   trials ran commands that read that history, and several cherry-picked upstream's security
   commits or moved the checkout to the fixed commit. No NEAT trial did. The bare arms were also
   working on a different problem: their OSV scan flags gitea's own 20 advisories by commit hash,
   and that is what they set out to fix, while the bench target is golang.org/x/net. The one bare
   trial that used no history (bare-sonnet `gitea-s2`) bumped x/net and then could not get the app to
   rebuild, at the turn cap. The per-trial table's last column counts these commands. The earlier
   k=1 pilot (`runs/gitea-real-k1-2026-11-10T06-02-29-206Z`) has the same leak in its bare-opus
   trial, so the gitea cost comparison in the k=1 write-up does not stand either.
2. **The arms confound the model with NEAT.** bare-opus against NEAT plus Sonnet changes both at
   once. The bare-sonnet run was added to separate them, and on the two apps where it is clean and
   comparable on cost (uptime-kuma, paperless-ngx) the saving against Opus comes from Sonnet, not
   from NEAT.
3. **No prompt caching.** The harness sends no cache breakpoints, so every trial pays for its whole
   context on every turn (cache reads are 0 in every trial). It is the same for every arm, but every
   dollar figure is higher than a caching agent would pay, and a large tool result is re-billed on
   each later turn. NEAT's security tools returned about 100k characters per call on uptime-kuma,
   which is most of the NEAT arms' extra cost there.
4. **Two apps cannot be verified.** nodegoat's suite needs a browser stack and paperless-ngx's
   image ships no test runner, so `no-regression` and `not-degenerate` are `unverified` for both in
   every arm. Their results rest on the scanner and the journeys only.
5. **One bare-opus paperless failure was the bench's.** `paperless-ngx` (first trial) failed
   "actually works" because the redeploy did not re-collect static files after a dependency bump.
   The fix is in the harness since, and replaying that trial's saved patch under it
   (`runs/controls-2026-11-15T09-27-38-850Z-replay-paperless-ngx-bare-opus-s0`) passes both
   "vulnerability gone" and "actually works". The other two bare-opus paperless trials: one hit the
   $25 cost cap with the fix in place, one ended at turn 20 on an API refusal.
6. **One NEAT paperless trial had no NEAT answer, and full against lean is confounded there.** In
   the k=3 run every NEAT security call in neat-sonnet-full `paperless-ngx` (first trial) timed out,
   because a cold advisory scan of that app took longer than the tool timeout (fixed in NEAT #1622).
   The advisory cache was shared across trials, so later trials got answers the first did not. The
   supplement re-runs both NEAT arms with a per-app seeded cache copied to each trial.
7. **The recorded NEAT commit in the k=3 run is wrong.** Each `run.json` says
   `benchNeatSha: eb330c2f382f`. That was the HEAD of the checkout the build was copied into. The
   build itself is NEAT `b1e6654`: rebuilding that commit gives byte-identical files
   (`packages/core/dist/cli.cjs` sha256 `bb183208a968a0d5...`, `packages/mcp/dist/index.cjs` sha256
   `7334969f2ab4ef68...`). `run-suite.sh` now records the commit of the build it launches.
8. **NEAT was fixed against these apps.** Two NEAT changes in the build under test (#1616
   multi-ecosystem inventory, #1617 Go fix action) came out of earlier bench work on these same
   four apps. They are not held-out targets.
9. **Small sample.** Three trials per cell, four apps, one box, one day.
10. **On nodegoat the NEAT arms had no runtime data at route level.** The nodegoat standup sends
    telemetry under the service name `nodegoat` (`nodegoat/nodegoat-fresh.sh`), while NEAT extracts
    the app as `owasp-nodejs-goat`, the name in its `package.json`. The spans landed on a second
    service node and never attached to the extracted routes, and the divergences NEAT reported there
    are largely artifacts of that split. The NEAT arms' transcripts query `service:owasp-nodejs-goat`
    throughout. So what the NEAT arms did on nodegoat, clearing all six advisories in every trial,
    came from NEAT's static analysis (which dependencies first-party code imports), not from observed
    runtime behaviour. The other three apps send telemetry under the name NEAT extracts. Found on
    2026-11-15 after these runs; the standup is unchanged in this commit so the record matches what
    ran.
